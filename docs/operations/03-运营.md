# 03 · 运营手段

## 冷启动 4 步（第 1 周）

1. **发 V2EX** → 收集 3-5 条真实反馈
2. **修最痛的 2-3 个问题**（大概率是「签名警告」「配置步骤」「读图失败」）
3. **发小红书 + 知乎**（用修好的版本 + 截图）
4. **把反馈整理成 FAQ**，写进 README 和落地页（这也是 SEO 内容）

## 增长飞轮

```
发帖 → 有人下载/star → 有人提 issue/反馈
  ↑                              ↓
更新 FAQ/教程  ←  把反馈写成内容再发一轮
```

关键：**每一条用户反馈，都是一篇内容素材。** 用户问「怎么读图」，就写一篇「DeepSeek 怎么看图」。

## 可持续运营（每周 30 分钟）

- 周一：看 issue + star + 下载量，回 issue
- 周三：发一条内容（知乎回答 / 小红书 / 更新教程）
- 周五：上游 harness 有更新就同步 + 重打包发新版（`v0.x.x`）

## 数据复盘（每月一次）

| 指标 | 怎么看 |
|---|---|
| star 数 | GitHub 仓库页 |
| 下载量 | Releases 每个 asset 的下载数 |
| 落地页访问 | GitHub Pages → Insights → Traffic（后续可接 Google Analytics） |
| 搜索来源 | 搜「DeepSeek 客户端 / deepseek desktop client」看排名 |

## 持续发版建议

- 版本号用 `v0.x.y`，每次发版写 changelog
- 上游 harness 更新 → 同步 fork → 重打包 → 发新 Release（README/落地页的「自动更新」是卖点）
- 优先做**最能涨口碑**的：签名公证、Windows 体验、更顺的读图

## 避坑提醒

1. **别刷量**：V2EX/HN/Product Hunt 对刷 star/刷赞零容忍，会反噬。
2. **主动声明非官方**：避免商标/法律风险。
3. **签名警告是最大流失点**：在 README、落地页、每个帖子都给出「右键→打开」的明确指引，直到买 Apple 开发者证书做公证。
4. **别一次性铺太多渠道**：先 V2EX 拿反馈，修好再放大，避免「带病推广」。
